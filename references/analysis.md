# 逆向拆解与关键词规划

## 逆向拆解方法

从一个真实处境中的人出发，倒推他愿意迈出下一步的条件，再形成内容。分析时先理清决策理由，表达时把最重要的点击理由放到前面。以下是策划检查顺序，不是假设每个人都会线性走完；已有信息可直接复用。

主线：**此刻为什么需要 → 真正想得到什么 → 为什么还没行动 → 什么价值与证据让他愿意选我们 → 同屏为什么先点我们 → 怎样表达并让他放心迈一步 → 用反馈修正判断**。

### 1. 此刻为什么需要：人、处境、触发与入口

先确定本篇面对谁、发生了什么、决策有多急，以及希望发生的一项行动。区分使用者、影响者与付费者：员工觉得工具省事，不代表老板已经有采购理由。

| 当前需求状态 | 优先入口 | 分析重点 |
| --- | --- | --- |
| 问题已发生，主动找解法 | 故障/问题词，必要时加地区与服务词 | 用户怎样描述问题，下一步需要排查还是找商家 |
| 已有需求，正在比较 | 判断依据、区别与证据 | 为什么尚未选定，谁的条件更适合 |
| 尚未主动寻找，但有相关愿望 | 生活场景、机会、价值对比、自我或关系表达 | 什么会让他意识到值得了解 |

按人和场景分流，不给整个行业贴永久标签。空调故障可搜索维修，同一行业的预防保养内容可能面向另一种状态；每篇明确自己的入口。

需要扩展选题时，从行业联想事件、品牌、人物、政策、经济与生活变化，筛选与该人切身相关的方向。热点可选；涉及当下时事或热度须实际检索，记录日期、来源与适用范围。品牌联想、新闻热度与目标人群需求分别判断。

### 2. 真正想得到什么：功能、感受与关系

先问他想改变的具体事情，再追问这对他意味着什么。可从以下角度发现动机，不必逐项套满：

| 可能的期待 | 应落到的具体处境 |
| --- | --- |
| 恢复正常、减少损失 | 设备恢复使用，日常生活能继续 |
| 轻松、省力、时间可控 | 少做重复操作，工作不再挤占休息 |
| 愉悦、自我奖励、表达风格 | 自己看着喜欢，觉得生活有一点新意 |
| 被看见、关系、归属、尊严 | 心意能被对方接住，劳动能被理解 |
| 机会、能力与自主 | 学到可用技能，能判断或选择下一步 |

继续问“为什么现在更重要”“希望自己或他人怎么看待这件事”，直到答案能影响选题、交付或证据选择；不无限追问到抽象标签。美甲可能为自我愉悦或约会，不能默认女性为异性消费；维修用户也未必都把价格排第一。

### 3. 为什么还没行动：阻力、替代方案与内心冲突

区分不想要、没条件、不相信、嫌麻烦和不着急。价格、时间、操作成本、效果不确定、退出难度、对身份或关系的影响，都可能是阻力；先找最影响这一次决定的那个。

检查用户现在怎么解决：找别家、自己做、交给员工、继续将就、暂时不做。真实竞争不只来自同类产品；若他认为维持现状已经够好，需要先证明改变值得。

用一句内心话整理假设：**“我想___，因为___；但___，所以现在我选择___。如果___，我才愿意___。”** 这是策划记录，不是成稿模板。不强行制造矛盾；有明显拉扯时才展开，例如想保留积蓄，又想结束租房。

每篇优先选一个主要欲望、一个主要阻力。用用户原话、可见评论、实际咨询或使用记录支持；资料不足标为假设，并记下可能推翻它的反馈。不能把“怕被坑、爱面子、贪便宜”等标签当作已完成分析。

### 4. 什么价值与证据让他愿意选我们：值得、可信、可控

比较用户原本预期付出与获得什么，再核对实际业务能提供什么。预期差是一种切入方式；匹配急迫需求、消除麻烦、提供确定性或让人愉悦也可以直接成立。

| 决策疑问 | 需要呈现的事实 |
| --- | --- |
| 值不值得 | 具体交付、使用结果、适用场景及完整投入；有依据的价值与价格对比 |
| 能不能信 | 可核对的过程、演示、案例条件、评价来源；把承诺落到证据 |
| 我能不能做主 | 先报价还是先施工、重要费用、是否可拒绝、售后与退出条件 |

例如维修的“不懂技术”可能意味着怕失去选择权，可以用真实的检查费、报价确认和不修如何收费来回应。软件的“省时间”需用实际流程演示或测量支持，不能凭功能名编节省数字。

“我出技术，你出时间”只有在真实带教与合作条件成立时，才能承接无人机学徒的期待；不能把单纯售课包装为招聘。需要更强交付才能解决阻力时，提出服务改进建议并标待确认，不直接写成现有承诺。

需要跨行业启发时按阻力选读 [营销案例与迁移边界](marketing-cases.md)。案例帮助提出假设，不能代替本业务的证据。

### 5. 同屏为什么先点我们：点击理由与封面竞争

封面、标题的优先目标是争取目标用户CTR；从“与我有关”进一步做到“这一篇值得先看”。不只单独评价好看、刺激或文案顺口。

- 搜索内容观察目标查询下的可见结果；推荐内容观察同人群、同场景卡片。记录入口、日期、截图/链接与可见范围。分散样本不能称真实同屏，未看到画面只能给竞争假设。
- 比较邻近卡片的主信息、标题、承诺、证据与视觉层级，找到重复表达和未被满足的关键问题。公开点赞、评论不能证明CTR，也不能只挑所谓爆文忽略普通样本。
- 将第4步真实成立的价值、依据或问题压缩为一个点击理由。搜索型保留故障、地区或服务识别；推荐型让场景、愿望或矛盾与目标用户直接相关。正文不能兑现时改承诺，不靠更强刺激弥补。
- 封面与标题成组判断：封面突出一个主信息，标题补搜索词、场景或条件，允许必要重复。以缩略图检查文字大小、对比、主体和层级。大字报可以有效传达，装饰不能挤掉重点；“3秒”是设计目标，未测不能说已验证。
- 选择角度时说明“这类用户为什么可能先点”，并保留一个合理的失败解释。例如老板与员工的冲突可能只吸引吐槽者，需要观察是否带来真正的工具需求。

### 6. 怎样表达并让他放心迈一步：语境、兑现、行动

中文词语同时承载字面意义、共同记忆与说话姿态。判断谁对谁说、在什么场合、是认真、调侃、反讽还是自嘲。热梗须核实当前用法和受众理解，不能只按字面理解，也不能把一个流行词当成跨行业必胜模板。

角色矛盾应落到具体行为：聚合发布软件可表现员工反复登录、发布的工作量与老板认知之间的差异。先判断要争取员工推荐还是老板购买，再决定视角；不把角色统一写成负面人物。

正文尽早兑现点击理由，提供解除主阻力所需的具体信息。教程给方法，服务说明给条件，体验文给真实感受；不强制每篇写成长教程，也不把内部心理分析生硬灌给读者。自然表达靠具体细节与口气，不能用虚构的客户故事、成果或“被问了三次”制造真人感。

下一步应是用户当前愿意承担的动作，说明付出和所得，例如提供故障信息以了解检查收费、提供发布流程以判断软件是否适用。不要在只建立初步兴趣时同时要求评论、关注、私信、购买；涉及费用或限额按真实情况说明。

### 7. 用反馈修正判断：分清哪一步没有发生

| 观察 | 优先核查 | 仍不能直接断定 |
| --- | --- | --- |
| 曝光很少 | 数据时间窗、来源、账号或笔记实际通知 | 文案失败，或一定被限流 |
| 有曝光但CTR偏低 | 人群匹配、同屏点击理由、缩略图识别 | 一定要更夸张、更焦虑 |
| 有点击但少有效咨询 | 是否兑现、信任证据、行动成本、受众是否匹配 | 只因正文不够长 |
| 有咨询但少成交 | 需求资格、报价与交付、响应及竞争方案 | 都是封面的问题 |

CTR按后台实际定义核验分子分母、时间窗和流量来源；不能将所有阅读量除以全部曝光量冒充官方点击率。同时看有效咨询及后续转化，有停留数据才评价停留。CQS沿用原五维模型，不推算CTR；具体计算见 [评分规则](scoring.md)。

改版尽量只变封面或标题中的一个因素，记录版本与时间，用可比窗口观察。先后改版不是严格随机实验，保留自然流量、受众与外部变化等解释。不因一次结果就断言某种心理机制成立，先修正假设再复测。

## 简短策划记录

策划时用以下记录把链路连起来，默认压缩呈现，用户只要成稿时可内部使用。不要每次输出大段心理学分析。

- **人和此刻：**谁，发生什么，处在哪种需求状态，使用者与付费者是谁。
- **内心话：**想得到什么，最主要的阻力是什么，目前选择什么替代方案。
- **凭什么选：**真实交付与证据怎样回应阻力，关键条件还缺什么。
- **凭什么点：**主关键词、竞争观察、一个点击理由、中文表达与封面主信息。
- **下一步：**用户付出什么、得到什么，业务怎样承接。
- **验证：**哪些已知、哪些假设，用什么反馈验证，什么结果会提示换方向。

## 笔记拆解

先列资料范围（完整/仅标题正文/仅摘要/无封面）及来源，再按决策链反查实际内容。输出观察、心理假设和缺失项，不替作者补造成功逻辑。

关键词表：位置｜原词｜核心需求｜搜索意图｜与主关键词的关系。主关键词取决于贯穿内容的需求，不按出现次数机械选取。最多提炼3个实际吸引词，注明位置与可能回应的期待；不足则如实说明。

封面只从可见画面判断，正文检查如何兑现承诺、提供证据和承接行动；无痛点的愉悦内容不强行补痛点。比较同屏时记录样本范围，不把高互动归因于某个词。提炼可迁移的决策机制，不复制独特表达、案例或经历。

## 关键词助手

三入口：
- 行业：大类→细分品类→具体问题→业务关联。
- 人群：身份/阶段→使用场景→限制条件→需求与顾虑。
- 内容：主题→具体问题→方法/清单/对比/避坑→期望结果。

这些入口用于收集背景，最终选词仍从用户想得到的结果逆推：他在什么场景下，会用什么原话搜索或表达需求，再连接到业务词；不要只围绕商家产品名扩词。

首次规划默认提供15–25个有区别的词即可，不堆积同义变体。组合例：[人群]+[场景]+[问题]、[核心词]+[限制条件]、[核心词]+[方法/结果]；只组合语言自然、意图一致的词。

真实检索时先用核心词，再扩展检索可访问的相关笔记和联想建议，记录查询词、来源链接、日期、样本范围。建议样本5–10篇，受访问限制则如实报告实际数量，不把搜索引擎联想称为小红书联想。热度只能依据实际平台指标；样本出现次数称“样本频次”，不是平台搜索量。

输出表：关键词｜类别｜人群/场景｜搜索意图｜证据类型与来源｜热度或未知｜推荐用途。候选推演词标“待验证”。给出3–5个内容选题簇，每簇一个主关键词与配套长尾词，并解释与业务的关系。

需要扩展挖词渠道和发布后验词时，读取 editorial-methods.md 的关键词工作流。不要将第三方网站所说的词密度、排名权重或平台功能当成已核实事实。

需要小红书笔记作为关键词或拆解样本时，先读取 [站内样本搜索](sample-search.md)，优先站内搜索与详情读取，明确区分卡片信息和完整笔记。
